Análises de mineração de dados para apoio à decisão

Site estático com três estudos de caso em datasets reais do Kaggle, cada um com EDA, mineração (clusterização, classificação, associação/limiar) e recomendações no formato decisão. Os notebooks 01–03 foram executados de ponta a ponta sobre os dados reais; cada página usa amostras reais de 200 linhas para navegação. A síntese comparativa está em Relatório.

Os três casos

E-commerce brasileiro (Olist) — ver análise

Dados reais — Olist Brazilian E-commerce (olistbr/brazilian-ecommerce, 99.441 pedidos, 112.650 itens, 95.420 clientes).

  • Volume: 99.441 pedidos (2016–2018), 112.650 itens, 95.420 clientes únicos no join.
  • Técnicas: KMeans k=4 sobre RFM, árvore de decisão (acurácia 0,69), co-ocorrência de categorias.
  • Holofote: a nota média cai de 4,21 (no prazo) para 1,70 (>7 dias de atraso) — priorizar estoque regional protege a satisfação.

Saúde (Diabetes) — ver análise

Dados reais — BRFSS 2015 (n=253.680, prevalência 0,139).

  • Volume: 253.680 indivíduos, 21 indicadores de saúde.
  • Técnicas: KMeans k=3 (perfis de risco: 34.806/128.569/90.305), árvore de decisão (acurácia 0,659), Apriori (15 itemsets, 22 regras).
  • Holofote: top fatores — pressão alta, IMC, idade, saúde geral e renda; regra de triagem — pressão alta + colesterol alto + idade avançada, ou IMC ≥ 30 + sedentarismo, identifica quem encaminhar ao rastreio prioritário.

Fraude em cartão de crédito — ver análise

Dados reais do Kaggle (mlg-ulb/creditcardfraud).

  • Volume: 284.807 transações europeias, 492 fraudes (0,17%).
  • Técnicas: KMeans, árvore vs. regressão logística, análise de limiar por custo esperado.
  • Holofote: perder uma fraude custa 50× uma revisão manual (FN=500 vs FP=10) — o limiar de custo mínimo (0,98; precision 0,562, recall 0,831) privilegia recall.
